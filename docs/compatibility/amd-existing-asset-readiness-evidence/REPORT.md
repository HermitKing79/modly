## S&box feasibility

Facepunch's [Model Editor documentation](https://sbox.game/dev/doc/editor/model-editor) lists FBX/OBJ/VOX/DMX/SMD; its [ModelDoc introduction](https://sbox.game/learn/facepunch/modeldoc-basics) recommends FBX or OBJ and documents texture import. **Direct GLB import is not established by those first-party sources or these candidates' evidence.** The documented [Color vertex semantic](https://sbox.game/dev/doc/rendering/shaders/reference/vertex-input-semantics) shows shader capability, not proof that a supported conversion/import preserves these COLOR_0 streams or that a stock material displays them.

The selected panel fits the existing Phase 21 GLB→OBJ/MTL/PNG conversion-and-independent-readback **pattern**, followed later by VMDL/material work. Its script is asset-specific and cannot be run unchanged: it assumes the earlier model's counts and one neutral image. This panel needs a new explicit input contract, two image roles, preserved normals, opaque/double-sided treatment, scale/orientation/pivot and clamp sampling. The installed first-party `core/shaders/common_samplers.fxc` contains `g_sTrilinearClamp`; this is an available route, not completed per-asset proof. Reusing Phase 22's wrap sampler or constant neutral roughness/metallic would misrepresent this asset.

Foliage and both whole color-only models first need a supported-format COLOR_0 transport/readback qualification, plus a shader path that actually uses it. Do not silently drop color through the Phase 21 converter, whose qualified export disabled vertex colors. None of the three families has an authenticated S&box import/render/performance result. Phase 22C proves only the separate neutral material's operability.
