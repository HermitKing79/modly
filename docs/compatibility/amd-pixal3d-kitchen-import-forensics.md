## Narrow capture design

New entrypoint: `scripts/compatibility/Invoke-Pixal3DKitchenImportCapture.ps1`. It defaults to no work and requires both `-CaptureKitchenImportOnly` and `-ApproveKitchenImportCapture`, plus the exact reviewed commit. Those switches deliberately approve this capture only. The existing operator PowerShell, host, controller, worker and `operator_execution_hold:true` remain held. The shared deny policy was moved without changing its AST/permissions.

The controller authenticates the unchanged V2 prefix and the original 13-wheel closure, plus the pinned packaging 25.0 ZIP overlay. It validates usable whole-process pidfds against the target kernel before ready/GO: open and poll a self pidfd, then check the actual kernel `pidfd_send_signal` API using signal zero, which delivers no signal. Kernel or permission failure closes the probe and stops. Worker checks require the matching authenticated-ready receipt, nonce, active controller/worker, PGID/start identities and its own pidfd preflight before Torch. Unsupported or ambiguous identity stops without fallback or signalling a numeric group.

The capture child imports real Torch, performs existing identity/device/VRAM admission checks, then imports Kitchen exactly once. It calls no INT8, ConvRot, SDPA, NAF, sparse, conversion or model function. It observes rather than resets tempfile/module/cache-env state. **Import itself can load HIP and initialize/query the GPU**: Kitchen `flash_attention.py` imports HIP and native registration queries visible GPU architectures. This is not a claim of zero possible native GPU activity.

The first denied filesystem event is synchronously recorded and flushed, then the process immediately self-exits with **23**. Imported Python cannot catch that stop. The rejected operation is never permitted. Logging failure exits **24**, making the capture fail rather than continue without evidence. Raw event/arguments, dir-fds, cwd (best effort), entry/resolved-path observations, descriptor identity, UTC/monotonic time, phase and caller frames are saved privately. Path observations are not permission grants: unlink addresses the candidate entry, while realpath may follow symlinks; resolved components are not pinned, and uncertainty is recorded.

If import finishes, logging stays armed throughout Python atexit. A later denial is labelled teardown rather than import. Both capture and observer hard-fail ordinary unraisable/atexit exceptions. The capture scope therefore preserves shutdown evidence instead of closing its log too early.

After the capture process is reaped, **one query-only cleanup observer**, using V2 and no Kitchen import, checks GPU identity, free VRAM >=3 GiB and zero owned Torch allocations. This is necessary because immediate exit cannot perform Python-side cleanup or measure VRAM afterward. It performs no numerical checks and is never a capture retry. Both processes must terminate without supervisor-forced cleanup; post-exit host RAM and V2/overlay preservation are recorded. A diagnostic PASS means evidence collection completed, never HIP/operator/generation qualification.
