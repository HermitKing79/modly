# Experimental AMD Image Test panel

**Corrected private application UI smoke, independent outcome review, and preservation: PASS within the recorded scope.** This report records actual input testing through the existing native picker, renderer, and owned local API. AMD generation remains unqualified. Base: `93d59af96c42535742214a72dbe95e329b982d72`.

The Generate workflow panel now offers **AMD Image Test**, using the existing Electron image picker and reader. It retains the original bytes and shows filename, dimensions, encoded size, transparency, foreground extent, and actionable CPU rejection reasons. An optional 2 MiB reader cap is carried through preload and IPC and checked before allocation; existing callers keep their omitted-cap behavior. Selection cancellation and revision checks suppress stale results. Uploads use the configured loopback API only, with redirects rejected.

`POST /amd/image-test` checks at most 2 MiB of original bytes. It requires a single RGBA frame, bounded dimensions, fully transparent background pixels, and a foreground above alpha 204 spanning at least three pixels on both axes. It calls the unchanged `admitted_image` contract, including its check after the original 1024-pixel resize. It does not convert JPEG/palette input to RGBA or remove a background. Bounded original CPU dimensions must be available before Chromium receives an image source or mounts a preview. Browser pixel inspection is labeled preliminary.

An eligible result means **original CPU input-contract admission**. The response keeps `preprocessing_complete=false` and `generation_qualified=false`: original image preprocessing, DINO/neural inference, mesh generation, and Generate authority are not exercised or qualified. The original API interpreter lacks Pillow. The explicit `MODLY_AMD_IMAGE_TEST_PYTHON` setting can select an existing compatible local Windows Python/Pillow runtime; no runtime is installed, discovered, or silently substituted. Missing/failed decoding remains unavailable. The optional CPU worker has bounded input/output, a ten-second deadline, and one active validation.

The corrected UI session accepted a synthetic 2,274-byte RGBA PNG (320 × 240; foreground 211 × 171) and displayed its checkerboard preview, original CPU eligibility, dimensions, and byte count. It rejected an opaque Windows wallpaper JPEG (833,851 bytes, RGB, 3840 × 2400) without RGBA conversion; that UI input was abstract wallpaper, not a photograph. A synthetic alpha-204 PNG produced a 0 × 0 foreground and was rejected. The reader blocked a 2,097,153-byte input before upload, and an 18-byte corrupt input showed a decoder rejection without mounting an image. The separate real landscape JPEG photograph (1,389,605 bytes, RGB, 6400 × 4000) was rejected by the CPU decoder's `not_rgba` check; its image and path remain private. This extra check is not another application run or an additional test method. Pending-selection races are covered by unit tests, not claimed as an observed UI interaction.

Canonical electron-vite/Tailwind tooling is unavailable in the existing dependency set; nothing was installed. The private smoke build bundles actual candidate main, preload, and renderer sources with existing packaged esbuild/dependencies and the existing Electron runtime. Its private main/bootstrap disables updater and builtin sync, blocks setup/SSL/install/destructive paths and external renderer HTTP(S), replaces the global port killer with a free-port assertion, and starts the current API through the original PythonBridge. Profile and writable app directories are private. The original picker, read IPC, and API validation are retained.

This is not canonical packaging verification. Installed compiled CSS is reused alongside source CSS; new Tailwind utilities are not regenerated. The actual application panel was visually reviewed as readable, and scrolling worked. Canonical CSS generation and release packaging remain unproved. An existing `three-stdlib` OBJLoader substitutes the pruned `three/examples` import only in the smoke build; no 3D-loader behavior is qualified.
